# 1.0.5 战斗过程诊断日志

本次增强与结算误判修复一起发布，不改变用户的试炼与出手规则。

## 可以追溯的过程

- 启动时记录程序版本与可读取的文件校验值、代理实例、加载的策略版本及策略内容。后续编辑策略不会改变已经保存的启动记录。
- 原生端保留最近最多 32 条界面和战斗状态事件（总大小上限 8 KB），每条带顺序编号、时刻、本场战斗标识、战斗结束标记、结算界面启用状态。
- 控制器读取历史事件，保存短暂的状态切换；若缓冲已覆盖未读取事件，会明确记录缺失编号。不能将“没有记录到”解释为“没有发生”。
- 记录结算对象伤害在未观察到界面启用时被读取的情况，每局至多一条，防止反复读取挤掉真正的状态变化。
- 首次观察到本场 BattleFinished 从未结束变为结束时，额外保存当时的回合、形态、英雄和 Boss 的生命、减益/增益及试炼状态。读取不到或内容超限会标出，不拿上一次出手快照充当终局状态。
- 分别记录用户配置触发的提前重整、必要试炼已不可完成、结算后目标未达成、结算状态冲突暂停，以及重整请求、接受/拒绝回执、控制器停止原因。
- 界面中的普通说明文字同时落盘；关键说明另外保存。账户绑定文字及原始地址/守卫转储会过滤。

## 文件位置与保留范围

Windows 用户数据目录：`%LOCALAPPDATA%\WFQ-GAFE\RaidBossStrategyStudio\logs`。

- 普通日志：最多 64 段，每段约 4 MB，合计约 256 MB。
- `critical` 子目录：结算、重整、停止、策略启动等关键事件另保留最多 16 段，每段约 2 MB，合计约 32 MB。频繁出手诊断不会直接挤掉这些记录。
- 清空工具界面的日志不删除磁盘诊断；重启工具也不清空文件。
- 文件按上限滚动保留，不承诺无限保存或绝不丢失；写入失败、状态事件覆盖、字段不可读取都有明确提示或标记。

## 分析时的界限

“结算后因 8000621 未完成而重整”只能证明重整分支，不能单独证明战斗为何结束。应对照本场标识、结束标记观察、终局快照、界面事件、目标检查和重整回执。`finishedReadStatus` 为 -1 表示当次无法读取，0 表示当次读到未结束，1 表示当次读到已结束；缓存的结束确认与当次读取状态分别保存。

已进行原生编译测试、事件缓冲容量测试、14 组 Python 离线测试，以及打包代码和原生 DLL 核对。没有在真实战斗中发出测试指令；游戏运行时若不能提供确认，程序会停止操作并保存诊断。
