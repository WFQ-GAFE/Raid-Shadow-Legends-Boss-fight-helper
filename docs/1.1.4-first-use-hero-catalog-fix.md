# 1.1.4 首次使用英雄资料恢复

## 问题

首次使用时，账号英雄名单已经读取成功，选人器能显示星级、等级、战力和属性，但所有名称仍是 `Champion <编号>`，头像是问号。

名单和显示目录是两条独立路径。全量英雄目录原先主要依赖游戏代理启动时的一次导出；首次导出不完整、被中断或本地目录缺失后，已经就绪的代理不会再次导出完整目录。选人器另行读取的静态资料未归并到显示目录，头像的前后端入口又都要求先有目录记录。进入 Boss 准备界面可能补上当前队伍的几名英雄，但不构成全量恢复。

## 修复

- 使用现有的隔离离线静态资料读取器自动补齐英雄显示与规则技能目录。正常账号轮询会消费后台结果，不依赖进入 Boss、开始战斗或重新加载游戏代理。
- 保留已有有效游戏名称、头像映射、技能槽位、形态与别名。静态资料缓存升级为 schema 5，保留完整升阶技能顺序，避免把替换技能或被动追加成额外按钮。
- 无目录时仍可根据合法英雄类型 ID 请求本地头像；已有游戏头像映射优先。首次缺少资源或存在不完整 bundle 时有界重试，只解码新增、变化或到期失败的源。成功源不重复解码，相同 PNG 不重写，缓存命中不等待全量解码锁。
- 资料或头像可用性变化时推进目录版本，当前窗口自动补齐名称、头像和高级筛选。已加载成功的头像不反复下载。
- 首次失败后，后台恢复和显式“重试”均可生效；重试保留当前队伍、搜索与筛选。加载和失败提示支持中文、英文、巴西葡语。
- 日志记录 `hero_catalog_loading`、`hero_catalog_unavailable`、`hero_catalog_recovered`，以及缓存保存失败原因。失败或空静态资料不覆盖健康缓存。

## 验证

- 51 个离线模块、369 个计数测试通过；其中新增纯目录恢复、服务接入和头像冷启动测试覆盖空缓存、延迟资源、首次失败后恢复、升阶别名、技能形态、成功缓存保护及坏 bundle 重试。
- 81 项界面测试通过，TypeScript/Vite 构建通过。真实组件测试覆盖打开中的选人器恢复、按真实名称搜索、保留队伍与筛选、保留健康游戏名称、版本变化后只重试失败头像。
- 原生离线组件构建通过，4 项现有代理 CTest 通过。
- 本次验证使用合成资料、临时目录、受控资源读取与离线引擎构建；未接管或启动实际游戏战斗。仍应由原反馈用户在其首次使用环境确认。

本次不改变游戏内代理；版本保持 1.1.4。开发包生成后由 `out/first-use-1.1.4-fix-20261016` 的验证收据记录其 SHA-256、内嵌前端、恢复模块和代理/离线组件校验结果。
