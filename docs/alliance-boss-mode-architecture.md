# 联盟 Boss 双模式架构

## 目标

同一个桌面工具承载奇美拉和六头蛇。账户、进程、英雄、技能、神话形态、图标、增益/减益、合法目标、技能提交、安全中断和日志内存缓冲全部共用；只把玩法确实不同的状态和策略分开。

## 分层

1. **共享运行层**：账户绑定、IL2CPP 反射、战斗英雄、技能冷却、效果剩余回合、合法目标、手动等待窗口和单回合一次提交。
2. **共享策略层**：严格规则优先；无严格规则可执行时才进入英雄默认技能顺序；默认禁用技能不会由默认规则释放。
3. **模式适配层**：
   - 奇美拉：固定形态序列、Boss 回合、试炼链、轮换奖励、必要试炼可行性和免费重整。
   - 六头蛇：四个在场蛇头、两个替补、吞噬/消化、斩首后的暴露蛇颈、复活/换头、总伤害和结果停留。
4. **界面层**：顶层选择模式，下面复用同一账户、队伍、目标、规则和运行控制界面。

## 单一数据源

- `cache/chimera-hero-catalog.json` 暂时保留旧文件名以兼容现有用户缓存，但内容是两个模式共同的全英雄/技能库，不会再建立 Hydra 副本。
- `config/raid-boss-strategies.user.json` 是统一策略容器，结构为 `modes.chimera` 和 `modes.hydra`。旧奇美拉策略会在首次读取时迁移进内存，首次保存后写入统一容器。
- 奇美拉试炼/奖励轮换仍是奇美拉专属数据；六头蛇不复制它。

## 六头蛇首版决策优先级

1. 正在吞噬且消化窗口紧迫的蛇头。
2. 需要打破生命护盾的蛇头。
3. 暴露蛇颈的伤害窗口。
4. 需要控制或阻止关键技能的危险蛇头。
5. 维持队友增益和蛇头减益。
6. 按英雄默认技能顺序输出。

规则目标支持正在吞噬的蛇头、暴露蛇颈、生命最低蛇头和当前场上 1–4 号蛇头。所有选择仍必须经过该技能的游戏内合法目标集合验证。

## 当前实机标定项

游戏元数据已经确认存在 `IsHydraBattle`、`HydraHeads`、`DevouredHeroId`、`DigestionInfo`、`HydraTotalTakenDamage`、`HeroesSelectionHydraDialogContext`、`BattleFinishAllianceHydraDialogContext`、`CancelHydraBattle` 和 `ExecuteCancelHydraBattleCmd`。代理已经加入这些类型的发现、六人准备队伍读取、多 Boss 快照、六头蛇战斗标记、总伤害 getter、结果页观察和技能提交守卫。

首次进入六头蛇准备界面和手动战斗后仍需用真实快照确认：

- 六头蛇的 `areaTypeId` 和 `kindId`；
- 四个蛇头的稳定位置字段；
- 吞噬英雄 ID 与消化剩余回合的实际字段布局；
- 蛇头与暴露蛇颈的运行时标志；
- 免费重整的响应阶段是否与奇美拉一致。

在这些值被正向识别前，六头蛇模式不会凭猜测启动接管。

## 机制依据

Plarium 的六头蛇说明确认：每场使用 6 名英雄，场上同时有 4 个蛇头；吞噬前有标记倒计时，吞噬后有消化倒计时；斩首后出现承受额外伤害的暴露蛇颈，随后会重新长出蛇头。实现只依赖游戏运行时对象，不依赖屏幕识别。
