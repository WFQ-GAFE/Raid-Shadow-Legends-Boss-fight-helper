# 1.0.6 队伍配置预览与分享

在 Boss 准备界面选好队伍后，工具读取每位英雄在游戏英雄界面上的整体数据，供自己检查，也随策略组导出给其他玩家参考。

## 使用

1. 用 1.0.6 预览版 r14 及以后启动工具（代理版本 2026092702，**更换代理后需要重启一次游戏**）。
2. 进入奇美拉或六头蛇的准备界面并选好英雄。“当前队伍”卡片下方出现“队伍配置”，打开后逐个英雄显示：
   - 星级、等级、觉醒星级、强化、战力、专精数量、已装备件数；
   - 整体属性：生命、攻击、防御、速度、暴击率、暴击伤害、抗性、精准，每项为总值以及“基础 | 加成”，与游戏英雄界面一致（不含进入战斗后的光环与效果）；
   - 套装、祝福、圣物、技能只用游戏图标显示，与界面语言无关：套装图标右下角为件数，圣物与技能图标右下角为等级；名称在鼠标悬停时显示。游戏里没有图标的隐藏技能不显示；
   - 专精：按进攻、防御、辅助分组的图标（悬停显示名称）。
3. 导出策略组时，如果有与该策略组队伍相同英雄的配置，会一并写入导出文件（`teamSnapshot`），导出提示会说明是否已包含；不含账号内的英雄实例 ID。导入后保存为只读的“作者的队伍”，在“当前队伍”卡片中打开查看；再次导出时原样带上。

## 数据来源

代理（`src/agent/agent.cpp`，`capture_team_preview`）只在游戏窗口线程、准备界面所选英雄变化时运行（失败 5 秒后重试），不改变任何游戏状态，结果写入共享内存槽 `team_preview`：

- 英雄：`UserReadGuard.Heroes.GetHero(int id)`（该方法另有 `Nullable<int>` 重载，代理按参数类型选取 `int` 版本；r13 误用了另一重载，导致只有英雄 ID、没有英雄数据），用游戏的 `JsonMain.ToJsonStr` 序列化（`t` 类型、`g` 星级、`l` 等级、`e` 强化、`s` 技能、`m.m` 专精、`da.g` 觉醒星级、`da.b` 祝福）；战力来自 `HeroesWrapperReadOnly.GetHeroPower`。
- 整体属性：游戏英雄界面使用的 `DefaultHeroStats.Base(user, HeroWithForm)` 与 `DefaultHeroStats.Bonus(user, HeroWithForm, 已装备神器, 圣物)`，总值 = 基础 + 加成。
- 装备：`UserReadGuard.Equipment.GetHeroSlotArtifact(heroId, 1..9)`，只取装备位、套装、星级、稀有度，用于统计套装件数。
- 圣物：`RelicsWrapperReadonly.GetFirstRelicByHeroId(heroId)` 给出圣物 ID，再在 `get_Relics()` 列表中找到该圣物读取类型、阶级、等级；`RelicsByHeroId(heroId)` 的全部圣物用于计算加成。
- 名称：套装、祝福、圣物用游戏本地化键（`l10n:artifact-set/name?id={0}#static`、`l10n:blessing/name?id={0}#static`、`l10n:relic/name?id={0}#static`），专精按技能类型取名。
- 图标：套装与祝福的图标名由游戏自己的 `ArtifactSetKindIdExtensions.GetArtifactSetIconUrl`、`BlessingTypeIdExtensions.IconUrl` 给出；专精、圣物图标按 ID 命名。工具从游戏资源包中提取对应图片并缓存：套装图标在游戏安装目录自带的 `Raid_Data/StreamingAssets/AssetBundles/ArtifactSets`（精灵名如 `Protection`，对应 `UI/Sets/Protection`），祝福在下载资源 `BlessingIcon`（如 `Tranquility`），专精在 `MasteryIcons`，圣物在 `RelicIcons_1`；技能图标取英雄自己的资源包（`<英雄基础 ID>_s<槽位>`，被动技能也按技能 ID 末两位的槽位查找）。r14 曾误用 `Artifacts`（单件装备图）和 `BlessingIcons`（按 ID 命名），导致套装与祝福图标空白。

字段含义来自游戏程序集的 `[Json("…")]` 属性（离线用 Cpp2IL 导出类型定义核对）。r11 曾用 `SiegeBuildingSlotExtensions.TeamSetup` 组建队伍，但它只给出等级与星级（没有技能、专精、祝福、神器），因此改为上述来源；为战斗属性加入的离线 `team-stats` 模式也已移除。

## 验证

- 解码、名称与图标名、导出与导入由 `tools/test_team_preview.py`、`tools/test_strategy_transfer.py` 覆盖；界面用由已保存战斗中的真实英雄、专精、祝福、圣物构造的数据检查了显示与游戏图标提取。
- 代理部分需要重启游戏后在准备界面实测；读取失败时卡片会显示代理给出的原因（没有读到任何英雄时代理报告 `heroes_not_found`）。
