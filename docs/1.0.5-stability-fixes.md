# 1.0.5 稳定性修复

验收日期：2026-09-06。应用版本仍为 **1.0.5**，Windows 文件版本统一为 **1.0.5.0**。原生代理内部构建标识更新为 `2026090501`，用于识别本次重新编译的代理。

## 编辑与保存

- 切换 Boss、账户和刷新账户时，按 Boss 与策略组保留未保存草稿；界面显示保存状态。
- 保存期间继续编辑时，旧保存响应不会覆盖后续修改。
- 保存会核对已读取的策略版本。发现其他窗口更新时，保留草稿并提示创建副本；也可明确选择“载入已保存版本”。
- 本地存储可用时，同一页面来源的刷新可以恢复草稿。桌面程序使用私密 WebView 和临时端口，草稿不保证跨程序关闭保留；长期保留仍需保存策略。
- 已保存策略采用原子替换，并保留最近五份成功保存内容。`.bak.1` 是最近一次成功保存的内容。
- 损坏文件不会被当成正常默认策略覆盖。界面提供恢复最近有效备份、从导出文件恢复当前模式的入口；恢复前保存原始字节至 `.recovery-时间戳.json`。从导出文件恢复时，其他模式使用默认配置，原文件可用于继续找回其他内容。

## 运行与实时状态

- 每次启动建立独立的暂停事件，取消信号贯穿准备、创建子进程及子进程初始化；旧会话完成清理后才允许重新启动。
- 控制器使用本次启动的策略快照。界面显示正在执行的版本，并说明运行期间保存的修改将在下次启动生效。
- 刷新改为串行请求，支持取消、超时、响应归属校验；旧 Boss、旧账户及控制操作前的迟到响应不会覆盖当前状态。
- 界面显示最后更新时间和连接中断信息。
- 界面与控制器共用吞噬判断，兼容 `Digestion` 和被吞英雄效果中的目标信息。
- 目录只在内容变化时传输，日志使用游标增量读取，保留最近 800 条。血量、冷却和当前合法目标等战斗字段不再导致静态目录反复更新。
- 共享内存数据过大时发布完整错误帧及实际大小、容量，不再发布截断 JSON，也不会保留旧的可执行快照。

## 解释与结构整理

- 增加规则命中解释：实际评估的规则、条件通过情况、选中动作、合法目标及动作回执；保留原有规则优先级和执行语义。
- 展示六头蛇已观测标记序列、触发条件、已用与剩余重整次数，并解释中途接管时的记录限制。
- 提取策略存储、吞噬公共模型、控制器生命周期、目录传输、决策解释以及前端草稿和轮询模块。
- 修复 720 像素高度下的模式栏挤压及策略栏溢出。
- 增加离线测试统一入口，仅执行明确列入的离线模块，并发现模块内的测试函数。

## 验收结果

- `python tools/run_offline_tests.py`：9 组离线测试通过，其中生命周期 23 项、本次回归 12 项；原有策略模糊测试覆盖 30,000 个畸形输入。
- 在 `ui` 目录执行 `node --test tests/studio.test.cjs`：7 项通过，覆盖草稿、延迟保存、过期响应、日志及实际轮询 hook。
- TypeScript 检查及 Vite 构建通过。
- 原生代理 Release 构建成功，CTest 的共享 JSON 溢出测试通过。
- 隔离预览页面实测：Boss 切换、刷新账户后草稿仍保留；保存正常；中英文界面、吞噬标签、规则解释、小窗口布局通过检查；损坏文件恢复后还原原策略值并保留损坏原件。
- 本机隔离数据包含 1040 名英雄：首次 `/api/state` 响应 1,805,709 字节；目录未变且无新增日志时为 1,193 字节。实际响应大小随战斗状态、解释信息与新增日志变化。
- 打包自检退出码为 0。验收环境不能直接启动要求管理员权限的正式 EXE，因此另打包仅用于自检的免提权版本。两者 422 个归档条目的应用内容一致；`base_library.zip` 的 154 个内部文件也逐一一致，差别仅在 ZIP 元数据。正式交付保留原有管理员启动方式。

本次没有进行真实游戏长战斗或免费重整实测。离线和界面测试使用隔离目录，没有修改正式用户策略。
