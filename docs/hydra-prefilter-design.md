# 六头蛇开局筛选：前 N 次标记排除指定英雄

> 2026-09-25 清理说明：本文是研究阶段的历史记录。文中提到的研究期工具（历史重放 `replay-observed`、首回合投影、选择器探针、动作脚本校验等）和 `out/` 下的研究证据已删除；离线引擎现在只保留 `json-convert` 与 `forecast` 两种模式，验证基线与现行实现见 [1.0.6 开局吞噬顺序推演](1.0.6-hydra-devour-forecast.md)。

状态（2026-09-25 更新）：开局推演已实现为实验选项，复用“吞噬顺序重整”条件（前 N 次排除指定英雄可写成 N 条“第 k 个标记不能是所选英雄”）。推演在隔离原版引擎中用当前策略运行至结算或第 1000 回合，并在与已进行的实战回合逐项核对一致后才可触发免费重整；尚缺一场新战斗的提前预测验证。见 [1.0.6 开局吞噬顺序推演](1.0.6-hydra-devour-forecast.md)。

原状态：研究与离线验证中。当前发布的 1.0.6 没有未来标记预测功能。此文件定义完整目标，不能以“等标记实际出现后重整”替代完成。

## 用户确定的行为

- 可选开启开局筛选，设置 N 并选择不允许被标记的一个或多个英雄。
- 前 N 次按标记应用次数计算，包含开局第一次；不能按实际吞噬次数计数。
- 首次目标也参与条件校验，但预测研究的重点是之后的随机选择。
- 开始真实战斗并取得本场状态后，先在独立离线环境推演当前队伍与当前策略下的前 N 次标记。
- 只有得到已验证、覆盖所需 N 次的预测，才判定通过。任意一次命中禁止英雄即判定不合格，使用游戏自身免费重整流程重试。
- 缺随机状态、预测不足 N 次、版本不兼容或推演失败是“无法判断”，不能误判通过或据此反复重整。
- 默认关闭，不修改现有用户策略。UI 使用开关、次数、英雄多选，不恢复流程图编辑器。
- 重试沿用明确的次数上限，并校验账号、阶段及英雄实例；不能因为读取到另一队伍就开战。

## 必须先确定的随机模型

2026-09-21 已完成第一轮磁盘方法体核对：选择器使用 `BattleState.Random`，命中类型判定也使用同一状态；候选集合受死亡/缺席及最近救出历史影响。已实现单次选人的离线基础模块并验证算术。详见 [本机随机算法核对](hydra-rng-research.md)。仍未实现开局未来序列预测。

“使用随机数”不足以证明“开局已存好固定英雄队列”。至少需要检查：

1. 是否已经生成独立的未来标记队列，可以只读复制。
2. 是否使用标记专用随机流；若是，需要复现其状态、候选人过滤、权重、去重和重抽。
3. 是否与伤害、弱击、效果命中、头部重生等共享随机流；若是，必须完整重放影响随机调用顺序的事件，不能仅凭一个种子直接生成英雄名单。

预测必须绑定游戏版本、同一场战斗、相同英雄实例/配置及策略版本。实际轨迹发生分歧后，旧预测失效，应从一致状态重新计算或显示无法判断。

## 2026-09-20/21 实测样本的约束

开局状态在首次玩家指令前、初始标记已放置后取得。524 个去重后的战斗快照、独立终止快照和确认过的结算记录已保存。

标记应用顺序：格雷尼特 → 疯帽客 → 缇塔斯 → 佩洛普斯 → 多纳泰罗 → 威克斯维尔。

实际吞噬顺序：格雷尼特 → 疯帽客 → 佩洛普斯 → 多纳泰罗 → 威克斯维尔。

缇塔斯在被标记之后、实际吞噬之前死亡，标记改选佩洛普斯。因此，若禁止英雄包含缇塔斯，N ≥ 3 时本样本不合格；不能因为实际吞噬名单没有缇塔斯就判断通过。样本不足以证明其他战斗的未来顺序。

最后一次吞噬在终止快照中；最后一个普通决策快照仍是 finished=false。分析器必须读取独立终止记录，不能仅取最后一帧决策。死亡英雄还可能保留历史 Devoured 效果，不能把这种残留当作头仍在同时消化多名英雄。

这场样本在第 346 回合进入结算，伤害为 2,416,604,768/8,000,000,000；结算记录是 `awaiting_user` 且 `resultSaved=false`，不能据此断言服务器已保存胜负。控制器明确记录伤害未达目标，并开始第 1 次免费重整。约 0.4 秒后已看到六头蛇准备界面，不是 30 秒界面转换超时；但界面队伍类型 ID `9006,9226,8256,8556,10676,9176` 与开战保存队伍 `8896,9906,9516,10416,9956,10056` 不同，随后以“当前6人队伍与策略组保存队伍不一致（具体英雄副本）”停止，退出码 5。这是英雄副本校验触发的安全停止；日志没有“必要试炼不可完成”的判断，也没有证据表明是试炼误判或伤害结算竞争。后续自动重试必须验证准备队伍，必要时按已授权保存队伍重新选择并再次确认，不能直接删除该检查。

## 旧样本的策略回放校验

2026-09-23 新增 `tools/verify_hydra_policy_replay.py`，将旧采集中的策略快照、已记录决策和对应战斗状态交给同一套控制器策略判断器重新评估。与两份重叠目录去重后，239 个已提交动作全部匹配记录中的技能与目标，未配对动作 0、策略分歧 0。报告还保存可机器读取的动作轨迹，包括动作前的状态摘要和技能/目标合法性；原始报告保存在 `out/hydra-observation-20260920-2352-gafee-detail/strategy-replay-validation.json`，总分析文件同时列出此策略一致性结果。

这只证明“给定当时记录的状态和规则，策略选择器能重现已提交动作”。它不证明原版 `BattleProcessor` 能逐步重现用户战斗，不证明随机调用轨迹相同，也不提供未来标记预测。报告把后三项分别标为未验证；因此该旧样本仍不能用于开局筛选或自动重整判断。

## 完成标准

- 找到并验证本场随机状态及目标选择实现，区分真正战斗 RNG 与 Unity 特效 RNG。
- 离线状态复制不推进或改写真实战斗对象，不调用真实随机发生器取下一个数。
- 同一捕获状态在离线环境重复推演结果一致，输入状态保持不变。
- 使用上述策略回放校验确认离线策略对记录状态的决策与实际提交命令一致；这只是必要的软件检查，仍须补齐原版战斗引擎回放及 RNG 调用轨迹验证。
- 已知样本验证完整标记事件序列，并覆盖死亡改选、救出、再次标记、头部重生与结算吞噬。
- 至少一次新战斗在后续标记出现之前保存预测；随后逐次与真实结果对比，记录首个分歧。
- 验证不合格通过正常免费重整返回同一队伍；合格才按当前策略继续。
- 提供来源、预测覆盖长度、命中条件、重试结果及失效原因的诊断日志。

## 现有能力与尚缺数据

现有控制器可观察已经出现的标记，并对特定位置配置允许/禁止英雄；不具备开局未来预测。历史样本已取得部分战斗 RNG 检查点和一场完整的 `BattleSetup`、`BattleSettings`，但还没有全部内部战斗事件、所有玩家回合的同义策略状态，也没有新开局的预测验收。

普通快照 RNG 字段、选择器调用前后状态和英雄当前属性记录已加入研究代理。研究构建另有一次性开局输入采集：使用游戏自己的 MessagePack 序列化当前 BattleSetup 与 BattleSettings，并记录场次 ID、种子和引擎版本；离线提取器将已停止采集中的输入复制到独立 replay 目录。2026-09-20/21 的旧样本来自 build 2026091301，既没有此输入，也没有随机状态，所以不能作为开局预测依据。

2026-09-25 的 gafee 新样本已有真实开局输入和同版原版运行库。隔离重放按历史记录执行 233 次玩家技能，推进到游戏第 306 回合；前 74 次的行动前 RNG 四字与实战记录一致，后 159 次没有 RNG 检查点。三次抽样标记目标及其回合与实战日志相符。保存的策略在前 74 个原生决策快照上也选出了相同的技能和目标。这仍是把**已知历史技能**喂给引擎的事后检验，既没有自动投影每步策略输入，也没有提前生成新战斗的标记序列。当前重放的冷却参数仍属研究假设；完整策略驱动、事件流覆盖和新战斗的提前预测验证仍是完成标准。
