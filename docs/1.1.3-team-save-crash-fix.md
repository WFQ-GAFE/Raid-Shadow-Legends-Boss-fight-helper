# 1.1.3 自选队伍保存崩溃修复

2026-10-04 09:10 左右，选择账号内英雄组成策略队伍并保存时，RAID 游戏发生 `0xc0000005` 非法内存访问。Windows 错误事件、Unity 崩溃日志及转储中的指令与工具代理调用链相互对应：`agent_window_proc → capture_team_data → team_json → static_data_section → il2cpp_class_get_fields`。

游戏重新建立 AppModel 后，代理仍使用初始化时缓存的 StaticData 对象地址。保存队伍读取技能／精通名称时，从这个失效对象取得无效的类型指针并传给游戏 API。转储确认了无效参数与故障指令，但没有保存旧对象的完整堆内存，因此不把具体回收时刻当作已验证事实。

## 修复行为

- 每次解析静态资料都从当前 AppModel 取得 StaticData；当前对象不可用时返回缺失，不回退到旧对象。本地化对象也从当前静态字段重新读取。
- 队伍、英雄列表、账号加成和技能资料采集期间使用完整指针宽度的 GC handles 保护对象，结束或异常时释放；用户读取锁始终按作用域释放。
- 动态类型资料查找捕获访问异常，采集请求防止重入与覆盖，排队后再次核对游戏是否处于安全读取状态。
- 保存与创建策略组只使用已经取得的本地数据，先完成落盘；后台在代理版本兼容、账号一致且对应 Boss 准备界面空闲时自动补全缺少的模拟数据。完整包不重复读取游戏。
- 后台请求合并，同一未完成或超时请求不反复排队，晚到的数据仍可消费。明确完成的拒绝可在安全状态变化后有限重试；账号／策略修订发生变化时丢弃旧结果。
- 日志区分本地保存、后台排队、延迟原因、请求开始、失败、晚到响应和补全落盘，以便定位后续问题。

## 更新与使用

版本保持 1.1.3，游戏内代理 Build ID 更新为 `2026100401`。旧代理即使共享内存布局相同也会被版本检查拒绝。

测试修复版前，关闭工具并完全退出需要使用的 RAID 客户端，再重新启动游戏和修复版工具。策略无需删除或重新建立。保存后若提示模拟数据不完整，规则和队伍选择已经保存；数据可用时会自动补全，无需额外执行导出或打包操作。

回归验证使用临时策略目录、模拟 IPC、假的 IL2CPP 回调和离线 C++ 测试，不把正在运行的游戏作为崩溃复现对象。测试覆盖旧对象替换、初始化失败、损坏类型指针、对象保活、锁释放、保存落盘、并发请求合并、超时响应与账号边界。具体检查结果和打包校验保存在此次 `out/save-team-crash-20261004` 诊断目录。
