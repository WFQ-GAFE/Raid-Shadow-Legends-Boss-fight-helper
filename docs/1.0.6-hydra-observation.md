# 1.0.6：恢复列表编辑与六头蛇观测

> 2026-09-25 清理说明：本文是研究阶段的历史记录。文中提到的研究期工具（历史重放 `replay-observed`、首回合投影、选择器探针、动作脚本校验等）和 `out/` 下的研究证据已删除；离线引擎现在只保留 `json-convert` 与 `forecast` 两种模式，验证基线与现行实现见 [1.0.6 开局吞噬顺序推演](1.0.6-hydra-devour-forecast.md)。

已移除流程图编辑界面、转换/检查/试跑接口和实时流程执行；保留原有列表规则、技能保留、折叠、搜索、滚动和诊断功能。现有列表策略无需转换。旧流程配置会明确拒绝导入/执行，不会静默改用另一个动作序列。

预览版仍使用既有的 `RaidBossStrategyStudio-Flow-1.0.6` 数据目录；这是历史目录名，保留它是为了继续读取已保存策略。稳定版 1.0.5 与预览版的数据仍隔离。

`tools/observe_hydra.py` 是开发期独立记录器。它只打开已经存在的代理共享内存，权限为 FILE_MAP_READ，不注入、加载、调用游戏方法或发送指令。

输入是指定游戏 PID 和确切账号名。开局前启动，并确认 `status.json` 为 `waiting_for_hydra`。例如：

```text
python tools/observe_hydra.py --pid <PID> --account <NAME> --output out/hydra-observation-<TIME>
```

保存完整的决策快照、指令回执、生命周期、结算记录和诊断文本到 `raw.jsonl.gz`。状态变化索引存于 `timeline.jsonl`；运行状态每两秒写到 `status.json`。同时保留开始采集后新增的六头蛇控制器日志，记录其目录与运行 ID；这些日志在与原始回执和策略对应前标记为 PID 未验证，不能直接归属于被观测账号。

默认每 100 毫秒读取已发布内容；只保存序号变化的发布。最多等待开战 30 分钟，开战后最多采集 90 分钟，原始数据最多 512 MiB；观测到结算后继续 15 秒然后停止。创建输出目录中的 `STOP` 文件可停止记录，不影响游戏或控制器。

边界：现有代理没有导出战斗随机状态、随机调用顺序或完整战斗事件流。发布序号跳跃只表示未读取到某次发布，不能视作漏掉一次游戏动作；没有序号跳跃也不代表捕获了所有游戏事件。标记变化只能称为观测结果，不能宣称未来预测。同一英雄的标记若在相邻快照之间消失再重施，单靠快照不能发现；中途开始采集会标记为未观测到开局。

下一阶段以真实事件对照决定需补充哪些状态，再设计独立离线回放；未实现随机种子捕获或未来吞噬预测。
