# 1.0.5 结算确认与重整校验修复

读取结算对象伤害不再等于结算界面已经打开。程序必须观察到结算界面的启用事件，并取得本场已验证战斗的结束标记，才允许按原有目标设置重整。

- 原生端观察结算界面启用、关闭；新战斗、重新进入准备界面和更新的进行中战斗会使旧确认失效。
- 界面事件方法不适用当前游戏时停止接管，不退回伤害读取推断。
- 生命周期、结算记录和战斗快照加入本场战斗标识；控制器拒绝跨局、来源缺失及互相矛盾的状态。
- 最后一次技能之前的正常战斗快照不会单独阻止随后发生的真实结算；生命值不用于猜测是否已经团灭。
- 执行重整前再次检查；原生执行端还会检查界面是否仍开启及结束状态是否仍成立。
- 日志持久保存结算确认或拒绝原因、目标缺项、重整请求与回执，以及提前重整和必要试炼不可完成的依据。摘要过滤内存地址及账户信息。

版本继续为 1.0.5，发布入口仍为 build/release/AllianceBossStrategyStudio.exe。没有修改用户的英雄、技能规则或目标。

验证：14 组 Python 离线测试（包括正常奇美拉、六头蛇结算流程、冲突状态和持久日志回归），原生结算确认状态及事件缓冲测试和共享数据测试。打包后另核对控制器模块与原生 DLL 内容。没有通过实际游戏操作制造结算；因此游戏运行时事件能否被当前版本识别仍需真实运行观察，无法识别时会明确暂停。
