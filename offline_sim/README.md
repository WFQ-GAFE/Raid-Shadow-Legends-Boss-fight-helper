# 奇美拉独立离线原型（配套 1.0.5）

当前实现的是**公羊尾巴试炼链的人工模型验证**，以及**真实策略导出的数据检查**。它还不能计算真实英雄的试炼成功率，不能模拟完整战斗；六头蛇尚未实现。现有工作室版本保持 1.0.5，这个原型没有接入其 EXE。

## 使用边界

原型只使用 Python 标准库和已有本地 JSON 文件。它没有连接游戏、读取进程内存、加载游戏引擎、注入、联网请求或提交游戏动作的接口，也不导入现有实时控制器。可以把整个 `offline_sim` 文件夹复制到另一台离线电脑运行。

这是独立计算程序，不是操作系统级安全沙箱，也不是游戏检测规避方案。它不提供隐匿、篡改或控制真实随机结果的功能；它的边界也不能证明原有实时工具不会被检测。

策略在模型内只能选择当前角色已经就绪的主动技能和允许的目标。被动、禁用技能、冷却中的技能、错误行动顺序或重复动作都会被拒绝。随机发生器保存在引擎内部，策略收到不可变的当前观察，不收到种子、未来掷骰或引擎对象。批量测试包含所有样本，不挑选有利种子作为真实战斗建议。

## 运行

需要 Python 3.10 或更新版本，无第三方依赖。在包含 `offline_sim` 文件夹的目录执行：

```powershell
# 运行人工试炼链：两项策略，各 200 次
python -X utf8 -m offline_sim demo --runs 200 --seed 71

# 检查现有的真实策略；目录文件应来自已经保存的本地数据
python -X utf8 -m offline_sim prepare --strategy "chimera-marius team.raid-strategy.json"

# 运行本模块的离线测试
python -X utf8 -m unittest discover -s offline_sim/tests -v
```

`demo` 输出 `out/chimera-offline-demo/report.md` 与 `results.json`。报告展示固定的第一号样本，JSON 保存每一号样本的动作、当时合法技能、效果施加/抵抗/栏位占满情况、前后进度和停止原因。

`prepare` 默认读取 `cache/chimera-hero-catalog.json` 和 `cache/chimera-ui-catalog.json`，可用 `--hero-catalog`、`--trial-catalog` 指定其他文件。输出为 `out/chimera-offline-reference/report.md` 与 `bundle.json`；`--output` 可以指定新的输出目录。重复运行会更新该目录内的生成报告；工具拒绝用生成文件覆盖输入文件。

资料包仅包含选中队伍的英雄与技能目录、目标、推导的前置链以及来源文件摘要。不复制执行规则、重试操作或账号/进程专用字段。输入中的 `verified` 或类似声明无法打开真实模拟入口。缺少英雄或目标目录时会明确列为缺项。

## 已实现的人工链

| 阶段 | 人工模型规则 | 计数类型 |
| --- | --- | --- |
| 8000604 | 行动前拥有增加精准；成功向 Boss 施加 7 种测试减益 | 持久的效果身份集合 |
| 8000605 | 行动前拥有暴击率或暴击伤害增益，且 Boss 已有虚弱；累计达到设定门槛 | 合格直接伤害累计 |
| 8000606 | Boss 在伤害前已有虚弱与降低防御；一次主动施法达到设定门槛，排除敌方最大生命值伤害 | 单次合格施法最大值 |

模型中的五名角色、技能、伤害和施加概率均为人工测试设定。200 万累计门槛和 75 万单次门槛也只是测试参数。编号用于关联本地目录中的需求语义，并不代表该真实试炼已经验证。

当前调度会补必要增益、优先尚未接受的减益身份，并为后续单次门槛预留爆发。最后一次行动机会到来时可以释放预留，争取完成前一阶段。它仍是用于验证依赖和计数的条件策略，尚未实现完整团队搜索或最优性证明。

## 显式模型假设与未覆盖内容

- 一个窗口为 5 个模型 Boss 轮次，每轮五个角色按固定顺序各行动一次；没有真实速度或行动条计算。
- 技能先造成设定伤害，再逐条掷骰施加效果；同一条团队效果的一次掷骰决定对全队的施加。没有真实技能的复杂事件顺序。
- 冷却按所属角色行动机会递减。角色效果在自身动作结束时递减，Boss 效果在整轮结束时递减。
- 每个接收者有 10 个效果格，同身份效果刷新且不缩短时间；不处理强弱同类覆盖、多层毒或独特增益规则。
- 不同减益按测试身份去重，效果到期不会清除历史已接受集合。真实试炼的身份等价规则仍须校验。
- 后继试炼从下一动作开始，不将解锁动作同时算入下一项；真实同次施法解锁语义仍须校验。
- 主动技能的敌方最大生命值伤害仅用于验证排除条件；没有真实伤害公式。反击/组队攻击、持续伤害、被动、额外回合、变形均未生成。
- 没有 Boss 攻击、生命值和存活计算。发现预置死亡角色或无合法技能便停止，不会自动复活、补充行动或越过冷却。

这些简化只适用于人工夹具，不能作为“游戏中必定可以做到”的证明。模型中的动作校验是实现真实规则之前的基础约束。

## 真实队伍检查结果与后续顺序

本次本地 `marius team` 导出中的五名英雄全部匹配成功，三个已选目标展开为七项依赖：

- 公羊爪子：8000607 → 8000608 → **8000609**。
- 狮子爪子：8000616 → **8000617**。
- 蛇形爪子：8000625 → **8000626**。

战斗难度取目录外层的 `UltraNightmare`；条目内部的 `difficultyId` 表示链内级别，不能误当战斗难度。链顺序按形态、部位和级别推导，仍标为推导证据。

这三条真实目标链尚未实现动态模拟。要扩展它们，下一步应先定义并用已有离线回放校验：两回合施加窗口、成功次数与不同身份的区别、增益保护产生的眩晕阻挡事件，以及单次施法的伤害归属。不能把公羊尾巴测试成功率套用到这些目标上。

之后补齐每个英雄实例的属性与装备、升级后技能冷却、结构化技能与被动事件、Boss 状态和行动条，再按以下顺序扩展：

1. 真实试炼事件回放：逐事件核对进度变化，未知语义阻止预测。
2. 团队滚动规划：比较未来有限行动窗口、统一技能预约、失败后重规划；只允许使用当前已观察的信息。
3. 奇美拉完整战斗：伤害/治疗/护盾、死亡/复活、形态轮换、随机分布与全场伤害区间。
4. 六头蛇：在共用事件引擎上增加多头、吞噬、斩首、重生与轮换。

没有离线参考样本或完整机制时，保留数据缺项状态，不生成貌似精确的真实结果。

## 本轮验证

27 项离线测试通过；另执行了两种策略各 200 次的人工批量推演，保存全部 400 次结果。验证了目标和行动合法性、冷却、效果去重、容量与到期、抵抗、计数条件、施法边界、预留、随机可重复性、资料字段筛选、前置链与拒绝真实预测的入口。

测试只验证上述模型和工具边界，不验证尚未实现的 RAID 物理规则。主程序 EXE 的 SHA-256 保持 `d3f8bf6abc4738bc3973b12804100e9a9b0e97dcb7a55d3b7389b4684cc27da3`。
